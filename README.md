# AxisPlanner

Многоосевой планировщик маршрута для [Axis](https://github.com/rs-a-demyanenko/Axis), основанный на подходе [GyverPlanner2](https://github.com/GyverLibs/GyverStepper/blob/main/src/GyverPlanner2.h): очередь отрезков, предварительное планирование скоростей, проход вперёд для разгона и назад для торможения, ограничение скорости на поворотах.

В одном маршруте можно использовать **шаговые двигатели, шаговые с энкодерами и коллекторные двигатели с энкодерами**. Число осей и размер очереди задаются при компиляции:

```cpp
AxisPlanner<3, 8> motion;  // 3 оси, до 8 отрезков в очереди
```

Планировщик передаёт в `Axis::syncPort()` положение, скорость и ускорение каждой оси. Axis продолжает обслуживать драйвер, обратную связь, регуляторы, homing, концевики и контроль ошибок. Исходники Axis менять не требуется.

## Возможности

- Линейное согласованное перемещение произвольного числа осей.
- Разгон, постоянная скорость и торможение; треугольный профиль для короткого отрезка.
- Скорость, ускорение и торможение ограничиваются параметрами всех участвующих осей.
- Проход промежуточных точек, точки обязательной остановки и продолжение маршрута.
- Пополнение очереди во время движения без изменения уже исполняемого профиля.
- Абсолютные координаты и смещения относительно последней точки очереди.
- Общее торможение, немедленная остановка, отключение и авария всей группы.
- C++11, фиксированные массивы, без динамического выделения памяти.

## Установка

**Arduino IDE:** установите GyverMotor2 и GyverStepper, затем [Axis](https://github.com/rs-a-demyanenko/Axis). Добавьте ZIP этой библиотеки через «Скетч → Подключить библиотеку → Добавить .ZIP библиотеку». Axis пока устанавливается из GitHub вручную. Требуется версия Axis с `AxisSync.h` и `syncPort()`; проверенный commit приведён в [DEPENDENCIES.md](docs/DEPENDENCIES.md).

**PlatformIO:**

```ini
lib_deps =
    https://github.com/rs-a-demyanenko/Planner.git
```

До публикации исходников в этом репозитории используйте локальную библиотеку в каталоге `lib/AxisPlanner` вашего проекта. `library.json` фиксирует проверенную версию Axis; зависимости драйверов описаны в самой Axis.

## Подключение осей

```cpp
#include <Axis.h>
#include <AxisStepper.h>
#include <AxisPlanner.h>

AxisStepper<STEPPER2WIRE> x(5, 6, 7);  // STEP, DIR, EN
Axis<GM2::DIR_PWM> y(4, 9);          // DIR, PWM; нужен энкодер
AxisPlanner<2, 8> motion;

// После настройки пинов, масштаба, энкодера и begin() каждой оси:
// config.maxJerk = 0;  // Задать перед begin() обеих осей.
// motion.addAxis(0, x);
// motion.addAxis(1, y);
```

Полные настройки и обработка команд есть в примерах:

| Пример | Оси |
|---|---|
| [StepperXY](examples/StepperXY/StepperXY.ino) | Два STEP/DIR двигателя, положение по выданным шагам |
| [MixedXY_Mega](examples/MixedXY_Mega/MixedXY_Mega.ino) | STEP/DIR и DC с квадратурным энкодером на Mega 2560 |

Оба примера проверены компиляцией для **Mega 2560**. Двухосевой пример с текущей Axis не помещается в Uno/Nano ATmega328P по Flash и RAM. Другие платформы требуют отдельной проверки сборки и производительности.

Для шагового двигателя с энкодером используйте `AxisStepper::attachEncoder()`, как в Axis. Подключение к планировщику остаётся тем же. Можно также передать `motion.addAxis(0, x.syncPort())` или собственный `axis::AxisPort`.

## Запуск маршрута

Сначала выполните `home()` каждой оси и дождитесь успешной привязки. Затем добавьте точки:

```cpp
const double p1[2] = {10, 5};
const double p2[2] = {20, 10};
const double p3[2] = {20, 20};

axis::Result result = motion.addTarget(p1);
if (result == axis::Result::OK) result = motion.addTarget(p2);
if (result == axis::Result::OK) result = motion.addTarget(p3, true);
if (result == axis::Result::OK) result = motion.start();
// Проверить result. При ошибке подготовки очистить маршрут через clearBuffer().
```

В `loop()` постоянно вызывайте:

```cpp
motion.tick();
if (motion.ready()) {
    // Все оси достигли точки остановки и выдержали время установления.
    // Если в очереди есть продолжение, motion.resume() запустит его.
}
```

`ready()` возвращает `true` один раз после достижения точки обязательной остановки или конца очереди. `isBusy()` остаётся `true`, пока реальные оси не установятся в допусках Axis. Конец текущей очереди всегда имеет нулевую скорость. Если новые точки пришли уже во время остановки в конце очереди, они ждут `resume()`.

Управление подключёнными осями обслуживает `motion.tick()`, в том числе homing и удержание при неактивном маршруте. Во время маршрута **не вызывайте отдельно `x.tick()` / `y.tick()`**: синхронизацией владеет планировщик. Все вызовы выполняются из одного потока/задачи, вне ISR.

## Профиль и повороты

Используется трапецеидальный профиль второго порядка, как в GyverPlanner2. Ускорение меняется скачком. Для всех осей задайте **`config.maxJerk = 0` перед `begin()`**. При ненулевом ограничении рывка `start()` возвращает `UNSUPPORTED`; S-профиль Axis не накладывается поверх внешней траектории.

`setDtA(0.3)` задаёт эвристическое ограничение скорости на повороте, аналогичное GyverPlanner2. Геометрического скругления угла нет, поэтому при проходе угла с ненулевой скоростью вектор скорости меняется скачком. Это приближённый режим; постоянные ускорения внутри отрезков не описывают импульс в самой вершине. Для остановки в каждом непрямолинейном углу используйте **`setDtA(0)`**. На развороте скорость всегда снижается до нуля; по прямой движение продолжается. Для обязательного физического установления в конкретной точке укажите `addTarget(point, true)`.

Координаты — машинные единицы Axis: обычно мм, для вращательной оси — градусы. Скорость подачи измеряется вдоль численной евклидовой длины маршрута. При смешении мм и градусов значение подачи зависит от выбранного масштаба координат; индивидуальные ограничения Axis проверяются независимо. Рабочее смещение, интерполяция дуг, преобразование кинематики и автоматический выбор кратчайшего угла не добавляются. Вращательные координаты задавайте развёрнутыми.

## Остановка и ошибки

`stop()` тормозит вдоль текущего маршрута, при необходимости проходит ближайшую вершину и удаляет оставшиеся точки после остановки. После установления оси получают `Completion::STOPPED`, а `ready()` не срабатывает. Для дальнейшего движения задайте новый маршрут.

`brake()` немедленно тормозит подключённые оси и очищает маршрут; `disable()` отключает их. `emergencyStop()` устанавливает аварию всей группы. Способ аппаратной реакции на ошибку определяется `Axis::Config::faultAction`.

При ошибке любой оси, потере владения синхронизацией, недопустимой опорной траектории или задержке обслуживания весь маршрут отменяется. Сначала проверяются все задания, затем читаются/обновляются все оси, затем применяются выходы. Ошибка второй оси не приводит к выдаче новой команды первой оси. После устранения причины вызывайте `clearFault()`; если Axis утратила привязку, повторите homing.

## Производительность и проверки

Частота `tick()` для шаговых двигателей должна существенно превышать `maxSpeed * stepsPerUnit` каждой оси: импульсы выдаёт AxisStepper, максимум один на вызов. Расчёт очереди происходит при добавлении точки, поэтому тяжёлое пополнение очереди также занимает время основного потока. Размер очереди и число осей ограничены доступной RAM и временем вычислений.

Нативные тесты с настоящими исходниками Axis и драйверными заголовками:

```console
python tests/run_tests.py --download-compiler
python tests/run_tests.py --sanitize
```

Первый запуск загружает фиксированные зависимости; на Windows флаг `--download-compiler` при необходимости устанавливает переносимый Zig внутрь `.tools/`. На Linux/macOS используется установленный g++/clang++/Zig. Подробности API — в [API.md](docs/API.md), результаты и границы проверок — в [VALIDATION.md](docs/VALIDATION.md).

## Происхождение

Это самостоятельная адаптация алгоритма планирования GyverPlanner2 к внешним опорным заданиям Axis. Прямое управление `Stepper::step()`, Брезенхем, компенсация люфта и режим вращения `setSpeed()` из GyverPlanner2 не перенесены: драйверами управляет Axis.
