# API

`AxisPlanner<Axes, Buffer>` — Arduino-обёртка над `planner::Planner<Axes, Buffer>`. Оба параметра — ненулевые `uint8_t` (1…255); практический предел задаёт память платы. По умолчанию `Buffer = 8`. Размер очереди включает текущий отрезок; отдельная стартовая точка слот не занимает.

Все изменяющие конфигурацию и очередь методы возвращают `axis::Result`, кроме явно указанных `void`. Объект нельзя копировать. Оси и контексты портов должны жить дольше планировщика.

## Подключение и настройки

| Метод | Назначение |
|---|---|
| `addAxis(index, motor)` | Подключить `Axis`, `AxisStepper` или объект с `syncPort()` |
| `addAxis(index, port)` | Подключить `axis::AxisPort` |
| `setMaxSpeed(value)` | Подача вдоль маршрута; по умолчанию 20 единиц/с |
| `setAcceleration(value)` | Разгон вдоль маршрута; по умолчанию 100 единиц/с² |
| `setDeceleration(value)` | Торможение вдоль маршрута; по умолчанию 100 единиц/с² |
| `setDtA(value)` | Параметр скорости в углу, диапазон 0…1, по умолчанию 0.3 |

Нумерация осей начинается с нуля. Повтор одного `Core` под разными индексами запрещён. Настройки и подключение осей разрешены при пустой очереди и неактивном маршруте. Скорость, ускорение и торможение должны быть положительными конечными числами. Конфигурацию самих осей не меняйте во время выполнения маршрута.

Для отрезка с единичным направлением `u[i]` действуют ограничения:

```text
feed <= min(plannerSpeed, axis[i].maxSpeed / abs(u[i]))
accel <= min(plannerAcceleration, axis[i].acceleration / abs(u[i]))
decel <= min(plannerDeceleration, axis[i].deceleration / abs(u[i]))
```

Неподвижные компоненты не участвуют в этих минимумах. Для поворота между направлениями `u` и `v`:

```text
junctionSpeed <= min(segmentFeeds, cornerAcceleration * dtA / sqrt(2 * (1 - dot(u,v))))
```

Для коллинеарного продолжения допускается общая подача, для разворота задаётся ноль. Обратный и прямой проходы очереди дополнительно ограничивают скорости доступными расстояниями торможения и разгона.

## Очередь и запуск

```cpp
axis::Result addTarget(const double (&target)[Axes], bool stopPoint = false,
                       planner::Coordinates mode = planner::Coordinates::ABSOLUTE);
```

Размер массива проверяется компилятором. Данные копируются. `ABSOLUTE` — машинные координаты, `RELATIVE` — смещение относительно последней добавленной точки. При пустой неактивной очереди смещение считается от последнего измеренного положения Axis; перед такой командой обслужите `tick()`. Если маршрут ещё устанавливается в конце очереди, берётся его конечная опорная позиция.

Одинаковые соседние точки возвращают `INVALID_ARGUMENT`. Полная очередь возвращает `BUSY`, недопустимая координата — `INVALID_ARGUMENT`, выход за программные границы — `OUT_OF_RANGE`. Неуспешное добавление не занимает слот. Перед началом движения вся геометрия повторно рассчитывается от фактической начальной позиции; обновлённые границы осей также проверяются.

| Метод | Назначение |
|---|---|
| `start()` / `resume()` | Запустить очередь с нулевой начальной скорости |
| `startAt(nowUs)` / `resumeAt(nowUs)` | То же с явной меткой времени |
| `clearBuffer()` | Очистить неактивную очередь |
| `available()` | Можно ли добавить точку сейчас |
| `queued()` | Занятые слоты, включая текущий отрезок |
| `freeSlots()` | Свободные слоты памяти очереди |

Для старта нужны все подключённые и инициализированные оси, успешный homing, отсутствие ошибок и занятости, `maxJerk = 0`. Контрольный период группы — максимальный `controlPeriodUs` подключённых осей. Он не должен превышать `maxTickGapUs` ни одной оси. Начало/продолжение выполняется из состояния покоя; Axis проверяет измеренную скорость.

При пополнении активной очереди её ещё не начатая часть пересчитывается, а профиль текущего отрезка и его выходная скорость сохраняются. Поэтому добавленная точка не всегда позволяет избежать уже запланированного торможения последнего активного отрезка. Остановка по флагу `stopPoint` и завершение очереди требуют `resume()` для дальнейшего движения.

## Обслуживание и состояние

| Метод | Результат |
|---|---|
| `bool tick()` / `bool tickAt(nowUs)` | Обслужить входы, профиль и выходы; вернуть, остаётся ли маршрут активным |
| `bool isBusy()` | Движение, торможение или ожидание установления реальных осей |
| `bool ready()` | Однократное событие успешного достижения точки остановки |
| `planner::Status getStatus()` | `IDLE`, `RUNNING`, `SETTLING`, `STOPPING`, `FAULT` |
| `planner::Error getError()` | Причина общей ошибки |
| `double getPathSpeed()` | Текущая опорная скорость вдоль маршрута |
| `axis::MotionState getReference(index)` | Опорное положение, скорость, ускорение оси; jerk равен нулю между скачками |
| `uint32_t getPeriod()` | Общий период обновления регуляторов в мкс; до первого старта — 0 |

`getReference()` возвращает рассчитанное задание; фактическое положение берите у оси. Неверный индекс возвращает нулевой `MotionState`. До первого старта опорные координаты нулевые. `getPeriod()` не задаёт допустимый период обслуживания шаговых импульсов — `tick()` вызывается значительно чаще. В неактивном состоянии `tick()` обслуживает локальные режимы Axis и возвращает `false`.

`nowUs` — монотонный счётчик мкс по модулю 2³². Переход через ноль поддерживается; пауза на полный оборот счётчика не обнаруживается. Все оси получают одну метку времени. Используйте один источник времени для портов и планировщика; Arduino-обёртка использует `micros()`.

## Остановки и ошибки

| Метод | Поведение |
|---|---|
| `stop()` | Плавно тормозить по маршруту и удалить оставшиеся точки |
| `void brake()` | Немедленно применить `Axis::brake()` и очистить очередь |
| `void disable()` | Отключить выходы осей и очистить очередь |
| `void emergencyStop()` | Установить аварию осей и планировщика, очистить очередь |
| `clearFault()` / `clearFaultAt(nowUs)` | Обновить входы и попытаться сбросить ошибки |

Во время `STOPPING` и установления после `stop()` пополнение запрещено. Повторный `stop()` безопасен. После `stop()` итоговое событие — `Completion::STOPPED` на всех осях; после `brake()`/`disable()` действует семантика завершения самой Axis. `brake()` не ждёт физического установления; новый старт может вернуть `BUSY`.

Общие ошибки: `AXIS_FAULT` (ошибка или отказ чтения порта), `INTERRUPTED` (ось вышла из синхронного режима), `REFERENCE_LIMIT` (невалидное опорное задание), `TIMING` (задержка управления), `NUMERIC` (непредставимый профиль). Исходную аппаратную причину смотрите через `axis.getFault()`. Общая ошибка сохраняется до успешного `clearFault()`; `disable()` её не сбрасывает.

Сброс может вернуть `FAULT_ACTIVE`, если вход ещё активен/чтение недоступно, или `BUSY`, если измеренная скорость выше допуска. После успешного сброса очередь пуста. Если Axis утратила homing, повторный старт вернёт `NOT_HOMED`.

Программного таймаута установления у планировщика нет: используются защиты Axis (`maxFollowingError`, `followingErrorTimeUs`, диагностика энкодера и др.). Если отключить эти защиты, неподвижная ось может бесконечно оставаться в `SETTLING`.
